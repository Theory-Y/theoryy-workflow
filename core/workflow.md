# Workflow — core definition

> Delivered by the `theoryy-workflow` plugin; injected each session by its `SessionStart` hook.
> Don't edit in a consuming project — overwritten on plugin upgrade. Project-specific context goes
> in that project's `CLAUDE.md`.

## Workflow

1. If `OVERRIDE.md` exists in repo root, complete its items **before** any ROADMAP.md items.
2. Read `ROADMAP.md` (open TODOs, recent changes) to create or select a plan.
3. Read relevant subfolder `README.md` files.
4. For non-trivial work, create an action plan under `action-plans/`.
5. Present the plan to the user before executing.
6. Delegate agents or execute the plan.
7. Afterwards: update `ROADMAP.md` (check off TODOs, append notable changes) and update the local `README.md` via the `subdir-readme-author` agent.

Every document, comment, and docstring you write follows the house style below.

## OVERRIDE.md

If present in repo root, it overrides `ROADMAP.md` priority. Prompt the user to complete its items first, or fold them into `ROADMAP.md`. Delete `OVERRIDE.md` once resolved.

## ROADMAP.md

Repo-root **master** document: the single TODO list + log of recent important changes.

- Whenever you touch the repo, append open action items and notable changes.
- Keep it lean — TODO list + change log, **not** a knowledge base. Subfolder READMEs answer codebase questions.
- Architecture/design/brand detail belongs in the relevant `DESIGN.md` / `SKILL.md` / `BRAND.md`, not here.

## Subfolder READMEs

Each meaningful subfolder carries a `README.md` (purpose + local conventions). When you work in a folder, create or update its README so descriptions live next to the files (not in `ROADMAP.md`). Generated by the `subdir-readme-author` agent.

## House style

`/theoryy-docstyle` sets the wording of everything written into the repo. It maps each file type to one of three compression levels. Agent-readable files (`SKILL.md`, agent definitions, this file) get plain full grammar. Human docs (`README.md`, `DESIGN.md`, `ROADMAP.md`) get word-dropping. Code comments and docstrings get the fewest possible words. Invoke the skill before writing or editing any of them. The rules live there, not here. `/theoryy-commit` handles commit messages. `/theoryy-speak` handles explaining something to the user in conversation: answer first, short plain sentences, no meta commentary.

## Design philosophy

`/theoryy-philosophy` governs what gets built. Default `minimal`: no new feature while the
existing surface is under ~90% polished (known bugs, stale docs, failing checks count against it);
prefer deleting to abstracting; smallest shippable diff — no speculative machinery; re-read the
touched surface before extending it. The polish gate applies whether or not the skill is loaded —
invoke it at feature decisions for the method.

## Lifecycle pipeline (optional)

`/initiate` drives **brainstorm → plan → council → delegate** for a non-trivial job starting cold. `brainstorm` (diverge into distinct directions + forking questions); `plan` (converge into `action-plans/<slug>.md` with per-step owners + done-conditions); `council` (multi-lens panel — scope · simplicity · feasibility/risk · alternatives — returning go/no-go); then hand-off to a manager mode (`/orchestrator`, `/player-coach`, or `/commander`).

Each phase skill is independently invokable. `/initiate` sequences them and gates on the user at direction and go/no-go. **Opt-in** — for trivial/obvious tasks, execute directly. (Named `initiate`, not `init`, to avoid the built-in `/init`.)

## Nested delegation (optional)

Default is **flat**: main thread runs `/orchestrator` or `/player-coach` straight to executor tiers. Only for a job decomposing into several **independent sub-projects**, escalate to `/commander` (L1): one `middle-manager` (L2 player-coach) per sub-project, each running its own executors. Chain capped at two layers (main → manager → executor; executors are leaves) — each layer is lossy. Nesting needs a recent Claude Code (verified 2.1.177); on older hosts a dispatched manager degrades to inline execution, so flat always works.
